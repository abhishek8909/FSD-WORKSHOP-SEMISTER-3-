# Security Policy

## Supported Versions

Only the latest release receives security updates. Please upgrade before reporting a vulnerability.

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

**Do not open a public GitHub issue for security vulnerabilities.**

Instead, please report them privately using one of the following methods:

1. **GitHub Private Vulnerability Reporting (Preferred):** Go to the **Security** tab of this repository and click **Report a vulnerability**.
2. **Email:** Send details to `[security@yourdomain.com]` with the subject line `[SECURITY] Brief description of issue`.

### What to Include
- Description of the vulnerability and its potential impact
- Steps to reproduce or a proof-of-concept (PoC)
- Affected versions, components, or endpoints
- Any suggested fix or mitigation (optional)

## Response Timeline

- **Acknowledgment:** Within 48 hours of receiving your report
- **Initial Assessment:** Within 5 business days
- **Resolution & Disclosure:** Coordinated with you once a patch is ready

## Disclosure Policy

Please allow a reasonable window to investigate and patch the issue before disclosing it publicly. Credit will be given in the release notes/security advisory unless you prefer to remain anonymous.
